## 황예성이 한 일

### 1. 아이디어 구상과 문제 정의
- 제조업 비전 주제에서 출발해 출튀 감지를 거쳐 **오픈스페이스 알박기 감지**로 주제를 구체화했습니다.
- 융합교육관 스터디룸 14개를 직접 조사했습니다. 예약 없이 선착순으로 운영되고, 학교의 30분 자리 비움 규칙과 룸 앞 보관함(회색 바구니)이 있다는 점을 확인했습니다.
- 핵심 문제를 **"30분 규칙은 있는데, 지켜졌는지 확인할 수 없다"**로 정의하고, 판정 규칙(빨강 사용중 · 노랑 30분 미만 · 초록 30분 이상)을 정했습니다.

### 2. 기획서
- 6 Pager PR/FAQ 양식으로 문제분석지, PR, FAQ 19문항을 작성하고 PDF와 통합본으로 정리했습니다. → [0주차_아이디어구상](../0주차_아이디어구상)
- HKU Find A Seat, 2023 도서관 좌석 감지 논문, 국내 라즈베리파이 좌석 감지 논문, 대학 도서관 예약 시스템을 조사해 차별점을 정리했습니다. (룸 단위 판정, 기존 30분 규칙 활용, 감지 영역 자동 설정, 얼굴 미식별)

### 3. MVP 구현 → [3D테스트/mvp](3D테스트/mvp)
- YOLO11s로 테이블과 사람을 검출하고, **테이블 박스를 가로·세로 30% 넓힌 감지 영역** 안에 사람이 있는지로 재석을 판단합니다. 감지 영역을 손으로 그릴 필요가 없습니다.
- 사람이 10초 넘게 안 보여야 부재로 보는 가림 보정을 넣고, 30분 3색 판정을 구현했습니다.
- 상태가 바뀐 순간의 화면만 사람을 모자이크해 저장하고, **1일 뒤 자동 삭제**하도록 했습니다. 데이터(CSV)는 계속 남깁니다.
- 판정 규칙 테스트 6개를 작성해 모두 통과했습니다.

### 4. YOLO 검증 → [YOLO검증](YOLO검증)
- 회의에서 나온 "엎드린 사람은 못 잡을 것"이라는 우려를 미팅 중 바로 사진 6장으로 검증했습니다. **모델 6종 모두 6장 전부 검출**했습니다.
- 모델별 파라미터, 연산량, 파일 크기, CPU/GPU 속도를 측정해 **YOLO11s를 기본 모델로 정한 근거**를 만들었습니다. (평균 신뢰도 0.85, CPU 1장 94ms. YOLO11x는 0.95지만 CPU 602ms, 109MB)
- 실제 스터디룸 영상을 분석해 룸의 공용 테이블은 0.63~0.71로 잘 잡힌다는 것을 확인했습니다. (1인용 책상은 대부분 0.2 미만)

### 5. 3D 테스트 환경 → [3D테스트](3D테스트)
- 스터디룸 14개를 3D로 만들고, 가상 학생이 공부하다 짐을 두고 나가는 시나리오를 시뮬레이션했습니다.
- 룸마다 천장 카메라 시점을 렌더링해 **YOLO11s 서버로 실제 판정**하고, 룸을 클릭하면 실시간 카메라 화면과 검출 결과를 보여 줍니다.
- 렌더 112장으로 측정한 결과, 앉은 사람 검출률 98.2%, 룸 판정 정확도 92.0%였습니다.

### 6. 협업 환경
- 컴퓨터비전 과정 저장소(MODU_CV)를 실습·특강·프로젝트 순서로 정리했습니다.
- 팀 진행 기록 페이지를 만들어 날짜별 진행 상황, 실험 결과, 역할 분담을 공유했습니다.
- 역할 분담안과 1차 회의 보고서 초안을 작성했습니다.

> 문서와 코드는 생성형 AI(Claude)를 활용해 작성하고 정리했습니다. 문제 정의, 현장 조사, 사진 촬영, 판정 규칙과 수치 목표는 직접 정했습니다.
